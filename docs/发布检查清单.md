# DropKnow 发布检查清单

本文档用于验证 DropKnow macOS 应用发布前的完整测试，确保用户安装、首次启动和日常使用流程正常。

---

## 1. 安装前检查

### 1.1 系统版本验证

| 检查项 | 操作步骤 | 预期结果 |
|--------|----------|----------|
| macOS 版本 | 点击苹果菜单 > 关于本机 > 查看 macOS 版本 | 版本号 >= 14.0（Sonoma 或更新） |
| Apple Silicon / Intel | 关于本机 > 概览页面查看芯片类型 | 建议 Apple Silicon（M 系列芯片），Intel 兼容运行 |

### 1.2 磁盘空间要求

| 检查项 | 说明 |
|--------|------|
| .app 文件大小 | 通过 Finder 查看 DropKnow.app 包体积，估算解压后总占用（含数据库缓存） |
| 预留空间 | 建议预留至少 2GB 可用磁盘空间 |
| 检查方式 | 苹果菜单 > 关于本机 > 存储使用情况 |

### 1.3 旧版本迁移

| 场景 | 操作步骤 |
|------|----------|
| 曾安装过旧版本 | 1. 完全退出旧版应用<br>2. 将旧版 DropKnow.app 移至废纸篓<br>3. 安装新版<br>4. 首次启动后验证历史数据是否自动加载 |
| 数据迁移失败 | 检查 `~/Library/Application Support/DropKnow/` 目录是否存在旧数据库文件，联系支持 |

## 2. 首次启动权限

### 2.1 权限申请流程

应用首次启动时会依次请求以下权限，请按顺序验证每个弹窗：

```
启动应用
  ├── [请求] 文件访问权限（DropBox/桌面/文档）
  ├── [请求] 日历权限（可选，弹窗说明用途）
  └── [请求] 通知权限（可选，如启用）
```

### 2.2 权限说明

| 权限 | 用途 | 拒绝后果 |
|------|------|----------|
| 文件访问（桌面） | 监控桌面文件夹新增文件并自动导入 | 无法自动导入桌面文件 |
| 文件访问（文档） | 监控文档文件夹新增文件并自动导入 | 无法自动导入文档文件 |
| 日历 | 将文件到期/提醒写入日历事件 | 加入日历功能失效 |
| 通知 | 文件导入成功/问答结果推送 | 无推送通知 |

### 2.3 权限被拒绝的处理

| 权限状态 | 用户操作路径 |
|----------|--------------|
| 首次拒绝后想重新授权 | 系统设置 > 隐私与安全性 > [对应权限] > 找到 DropKnow > 打开 |
| 权限完全不可用 | 卸载重装应用（会重新触发权限申请流程） |
| 部分权限拒绝 | 应用降级运行，仅拒绝权限相关功能受限，其余功能正常 |

## 3. 真实文件导入测试

### 3.1 测试文件准备

准备以下真实文件（不要使用空文件或测试用假数据）：

| 文件类型 | 准备建议 |
|----------|----------|
| .txt | 纯文本文档，包含 3-5 段可检索的正文内容 |
| .pdf | 至少 5 页的 PDF，可包含文字和图片 |
| .docx | 包含标题、正文、列表的 Word 文档 |

### 3.2 导入流程验证

**步骤 1：手动导入单个文件**

```
文件面板 > 点击 "+" 按钮 > 选择准备好的 .txt 文件 > 确认导入
```

验证点：
- [ ] 文件出现在列表中
- [ ] 状态显示为"处理中"或转圈动画（< 5 秒）
- [ ] 状态变为"就绪"（Ready）
- [ ] 文件名和大小显示正确

**步骤 2：多文件连续导入**

依次导入 .pdf 和 .docx，验证：
- [ ] 每个文件独立处理，互不阻塞
- [ ] 列表中显示多个文件条目
- [ ] 每个文件最终状态均为"就绪"

**步骤 3：确认 Recent Files 出现**

- [ ] 打开应用后，Recent Files（最近文件）区域显示刚导入的文件
- [ ] 文件名、文件类型图标、导入时间均正确

**步骤 4：状态流转完整性**

检查每个文件的完整状态生命周期：

```
导入中 → 处理中 → 就绪
         ↓
       失败（如遇损坏文件）
```

## 4. 核心功能验证

### 4.1 搜索功能

**关键词召回测试**

| 测试用例 | 操作 | 预期结果 |
|----------|------|----------|
| 精确词匹配 | 在搜索框输入文件中存在的完整词语 | 文件出现在搜索结果中 |
| 部分词匹配 | 输入文件中词语的一部分（>= 2 个字符） | 匹配结果出现 |
| 多词组合 | 输入两个不同关键词（用空格分隔） | 同时包含两个词的文件出现 |
| 无结果场景 | 搜索一个不存在的随机字符串 | 显示空结果状态（非崩溃） |

### 4.2 详情页打开

- [ ] 点击任意已就绪文件，详情页正常打开
- [ ] 文件内容预览区域正常显示（文本可阅读）
- [ ] 文件元数据（名称、大小、导入时间）显示正确
- [ ] 返回列表页功能正常（back 按钮或手势）

### 4.3 问答功能

| 测试步骤 | 预期行为 |
|----------|----------|
| 在问答输入框输入关于文件内容的问题 | 发送后出现加载状态 |
| 等待 10-30 秒（首次可能更长） | 返回基于文件内容的回答 |
| 追问一个相关问题 | 应用能理解上下文，给出连贯回答 |
| 发送空消息 | 输入框不应提交，应有前端校验 |

### 4.4 打开原文件

- [ ] 详情页或列表中有"打开原文件"按钮/选项
- [ ] 点击后使用系统默认应用打开源文件
- [ ] 对应应用（PDF Reader / TextEdit / Word）正常启动并显示文件

### 4.5 加入日历

**成功路径**

```
在文件详情页 > 点击"加入日历" > 选择日期时间 > 确认
```

- [ ] 日历应用中出现对应事件
- [ ] 事件标题包含文件名
- [ ] 事件时间与选择一致

**权限拒绝路径**

```
在文件详情页 > 点击"加入日历" > 系统弹窗提示"日历访问被拒绝"
```

- [ ] 应用不崩溃
- [ ] 显示清晰的错误提示，引导用户去设置开启权限
- [ ] 用户可取消操作，返回详情页

## 5. 异常路径验证

### 5.1 无文件时启动

| 操作 | 预期行为 |
|------|----------|
| 全新安装后启动应用（无任何导入文件） | 应用正常打开，显示空状态页面 |
| 空状态页面文案清晰，引导用户导入文件 | 不崩溃，不显示错误日志 |

### 5.2 导入损坏文件

准备一个损坏的 PDF 或截断的假文件：

| 测试步骤 | 预期行为 |
|----------|----------|
| 尝试导入损坏文件 | 显示"处理失败"或相应错误状态 |
| 不阻塞其他正常文件的处理 | 并行处理不受影响 |
| 重复尝试导入同一损坏文件 | 给出一致错误，不重复弹窗 |

### 5.3 网络断开时行为

| 场景 | 预期行为 |
|------|----------|
| 导入文件后立即断网 | 本地处理继续进行，不依赖网络 |
| 问答功能在无网络时发起 | 显示网络错误提示，不崩溃 |
| 断网期间保持应用运行 | 不出现断网相关崩溃 |
| 恢复网络后 | 应用自动恢复，不需手动重连 |

### 5.4 配额超限提示

> 注：如果应用有存储配额或 API 调用配额限制，需验证以下场景。

| 场景 | 预期行为 |
|------|----------|
| 存储配额即将用尽 | 在界面显示警告横幅或提示 |
| 配额用尽后尝试导入 | 阻止导入并显示清晰错误信息 |
| 配额用尽后使用问答 | 提示配额用尽，不崩溃 |

## 6. 崩溃与日志采集

### 6.1 日志位置

| 日志类型 | 路径 |
|----------|------|
| 应用运行日志 | `~/Library/Logs/DropKnow/` |
| 崩溃报告 | `~/Library/Logs/DropKnow/CrashReporter/` |
| 数据库日志（如开启） | `~/Library/Application Support/DropKnow/logs/` |

### 6.2 如何报告问题

**报告问题时的标准流程：**

1. 确认应用版本（关于本机或设置页面查看）
2. 记录问题发生的时间点和操作步骤
3. 收集以下诊断信息（见 6.3）
4. 通过以下渠道报告：
   - GitHub Issues（推荐）：附上日志压缩包
   - 邮件支持：在邮件中简要描述问题并附上诊断信息

**收集日志命令（终端）：**

```bash
# 打包最近 7 天的日志
cd ~/Library/Logs
zip -r ~/Desktop/DropKnow_logs.zip DropKnow/ -x "*.tmp" -x "*.lock"

# 或只收集崩溃报告
cp -r ~/Library/Logs/DropKnow/CrashReporter ~/Desktop/CrashReports/
```

### 6.3 诊断信息应包含

提交问题报告时，请附上以下信息以便快速定位：

| 信息类型 | 说明 |
|----------|------|
| 应用版本号 | 例如 v1.2.3 |
| macOS 版本 | 例如 macOS 14.4 |
| 芯片类型 | Apple Silicon / Intel |
| 问题发生时间 | 尽量精确到分钟 |
| 操作步骤 | 触发问题的完整操作顺序 |
| 控制台日志 | `~/Library/Logs/DropKnow/` 中对应时间段的日志文件 |
| 崩溃报告 | 如果是崩溃问题，附上 .crash 文件内容 |
| 文件列表 | 如与特定文件相关，附上该文件的名称和大小（不要附文件本身） |
| 网络状态 | 问题发生时是否使用代理、VPN 或企业网络 |

### 6.4 隐私说明

- 日志文件中可能包含文件路径、文件名等信息
- **不要**在报告中附上文件内容或敏感文件
- 如有疑问，可在发送前用文本编辑器查看日志内容，确认无敏感信息后再提交
