# Plan 04-01：PR 门禁主流水线

作者：glm5.1+37chengshan

## objective
建立 PR 必过门禁：构建、测试、变更守卫，确保合并质量。

## tasks
1. 新建 `pr-gate.yml`，触发条件为 `pull_request` 到 `main`。
2. 运行 `swift build` 与 `swift test`。
3. 增加“拒绝提交构建产物”守卫（如 `.build/**`、`build/DerivedData/**`）。
4. 为构建与测试结果增加 artifact 上传步骤（如日志与测试结果）。
5. 在文档中记录 job/check 名称：`PR Gate / build-and-test`、`PR Gate / artifact-guard`。

## acceptance_criteria
1. AC-04-01-1：PR 到 `main` 自动触发门禁，检查名包含 `PR Gate / build-and-test`。
2. AC-04-01-2：构建或测试失败时，`PR Gate / build-and-test` 失败并阻断合并。
3. AC-04-01-3：PR 包含构建产物路径时，`PR Gate / artifact-guard` 失败并给出明确提示。
4. AC-04-01-4：成功运行后可下载日志/测试结果 artifact。

## verify
1. 本地执行：`swift build && swift test`。
2. 语法与注册检查：`gh workflow view pr-gate.yml`。
3. 失败样例验证：在临时分支制造可编译失败提交，创建草稿 PR，确认 `PR Gate / build-and-test` 失败。
4. 成功样例验证：修复后更新同一草稿 PR，确认 `PR Gate / build-and-test` 成功并存在 artifact。
5. 运行记录校验：`gh run list --workflow pr-gate.yml --limit 5`。
