# 数据库迁移清单

本文档基于以下设计文档统一后的结论生成：

- `落知_信息架构_技术架构_数据表设计_前端设计.md`
- `落知_状态机与错误码设计_v1.1.md`
- `落知_Prompt与JSONSchema_FewShot规范_v1.1.md`

目标是把早期表结构草案收敛到 Phase 1 可落地的 SQLite 真 schema。原则是：以状态机文档 v1.1 为真集，以 Provider Schema 为结构化结果真集。

## V1 实施落地记录（2026-04-18）

本清单对应以下落地文件：

- `DropKnow/Infrastructure/Database/schema.sql`
- `DropKnow/Infrastructure/Database/migration_v1.sql`
- `DropKnow/Infrastructure/Database/DatabaseInitializer.swift`
- `DropKnow/Infrastructure/Database/README.md`

执行顺序约定：

1. 启动时由 `DatabaseInitializer` 检查并创建 `schema_migrations`
2. 若不存在 `v1_initial`，执行 `migration_v1.sql`
3. `migration_v1.sql` 内在事务中应用完整 v1 schema、索引、FTS 与触发器
4. 成功后写入 `schema_migrations(version='v1_initial')`

## 统一口径

### 以 v1.1 替换的旧字段/旧枚举

| 旧口径 | 新口径 | 处理建议 |
|---|---|---|
| `documents.ingest_status` | `documents.lifecycle_status` + `documents.current_stage` | 停止新增 `ingest_status`，拆成业务状态和阶段状态 |
| `documents.event_status = candidate/confirmed/added_to_calendar/dismissed` | `none/has_candidate/has_accepted_event/has_calendar_event/all_dismissed` | 改枚举并迁移历史值 |
| `parse_jobs.status = queued/running/success/failed` | `queued/running/success/failed/skipped/cancelled` | 扩枚举 |
| `parse_jobs.stage` 无 `notify` | `import/parse/gate/summary/event_extract/index/notify` | 扩枚举 |
| `document_events.calendar_status = not_added/added/failed` | `not_added/adding/added/failed/feature_locked` | 扩枚举 |

### Provider Schema 回写数据库时缺失的字段

| 来源 | 当前表缺口 | 迁移建议 |
|---|---|---|
| `SummaryTask` | `location_signals`、`supporting_snippets` 未落库 | 为 `document_summaries` 增加 `location_signals_json`、`supporting_snippets_json` |
| `EventExtractionTask` | `raw_time_text`、`calendar_eligible` 未落库 | 为 `document_events` 增加 `raw_time_text`、`calendar_eligible` |
| 状态机 v1.1 | `documents.readiness_flags` 未落库 | 增加 `readiness_flags_json` |
| 搜索状态机 | 缺 `search_sessions` | 新增 `search_sessions` 表 |

## 迁移顺序

1. 建立基础表：`watch_directories`、`providers`、`subscriptions`、`usage_quotas`
2. 建立主业务表：`documents`、`document_texts`、`document_chunks`、`document_summaries`、`document_events`
3. 建立行为/执行表：`privacy_decisions`、`notifications`、`document_actions`、`parse_jobs`、`search_sessions`
4. 建立 FTS5：`document_chunks_fts`、`document_summaries_fts`
5. 建索引与唯一约束
6. 执行旧字段到新字段的数据回填
7. 最后删除废弃字段或停止使用

创建或改造为以下字段：

- 主键与文件元数据：
  - `id TEXT PRIMARY KEY`

  - `file_name TEXT NOT NULL`
  - `file_extension TEXT NOT NULL`
  - `absolute_path TEXT NOT NULL`
  - `file_hash TEXT NOT NULL`
  - `file_size INTEGER NOT NULL`

  - `modified_at_fs DATETIME`

- 状态字段：
  - `lifecycle_status TEXT NOT NULL`
  - `current_stage TEXT NOT NULL`
  - `block_reason TEXT NOT NULL DEFAULT 'none'`
  - `parse_status TEXT`
  - `parse_quality TEXT`
  - `summary_status TEXT`
  - `event_status TEXT NOT NULL DEFAULT 'none'`

  - `readiness_flags_json TEXT NOT NULL DEFAULT '{}'`

  - `importance_score REAL NOT NULL DEFAULT 0`
  - `last_error_code TEXT`
  - `last_error_message TEXT`

删除或废弃：

- `ingest_status`

枚举真集：

- `lifecycle_status`: `detected`, `processing`, `waiting_user_confirmation`, `ready`, `blocked`, `failed`
- `current_stage`: `import`, `parse`, `gate`, `summary`, `event_extract`, `index`, `notify`, `done`
- `block_reason`: `none`, `privacy_confirmation_required`, `quota_exceeded`, `feature_locked`, `unsupported_type`, `permission_denied`, `policy_blocked`
- `event_status`: `none`, `has_candidate`, `has_accepted_event`, `has_calendar_event`, `all_dismissed`

回填规则：

- `pending/watch_detected/queued` -> `lifecycle_status=detected`, `current_stage=import`
- `parsing/gated/summarized/indexed` -> `lifecycle_status=processing`，`current_stage` 按原阶段映射
- `candidate` -> `has_candidate`
- `accepted/confirmed` -> `has_accepted_event`
- `added_to_calendar` -> `has_calendar_event`
- `dismissed` -> `all_dismissed`

索引建议：

- `idx_documents_imported_at(imported_at DESC)`
- `idx_documents_lifecycle_status(lifecycle_status)`
- `idx_documents_current_stage(current_stage)`
- `idx_documents_event_status(event_status)`
- `idx_documents_watch_directory_id(watch_directory_id)`
- `idx_documents_file_hash(file_hash)`

幂等约束建议：

- 业务侧联合判定 `file_hash + file_size + modified_at_fs`

## 迁移检查项

### 必做数据修复

- 所有旧状态值迁移到 v1.1 真集
- `document_summaries` 回填空数组字段为 `[]`
- `documents.readiness_flags_json` 回填：
  - `has_text`
  - `has_summary`
  - `has_event_candidate`
  - `has_search_index`
  - `has_notification`

### 必做约束校验

- Swift 层所有状态 `switch` 不允许 `default`
- Provider 输出入库前必须先做 JSON parse、repair、schema validate
- `event_no_candidate` 不应把 `documents.lifecycle_status` 写成 `failed`
- `ready` 允许部分能力缺失，例如“摘要成功、事件失败”

### 上线前验证

1. 新文件正常走完 `detected -> processing -> ready`
2. 命中门禁进入 `waiting_user_confirmation`
3. 额度耗尽进入 `blocked(block_reason=quota_exceeded)`
4. `summary_invalid_json` 能 repair 并重试
5. `document_events.calendar_status` 覆盖 `adding` 与 `feature_locked`
6. Quick Panel 能根据 `search_sessions.status` 渲染 `loading/no_result/blocked/failed`
